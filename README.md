# Katzenpost Website

Source for [katzenpost.network](https://katzenpost.network), built with
[Hugo](https://gohugo.io/) and the [Docsy](https://www.docsy.dev/) theme.
Deployed by Netlify (see `netlify.toml`).

## Container preview and checks

The host needs Git, Make, and Podman. The container supplies Hugo, Node.js,
Go, Python, and the Mermaid parser.

```sh
make serve-bg
```

The command prints the preview URL. The server watches source changes and
publishes its port on `127.0.0.1` by default. Stop it with `make stop`.
`BIND` selects the host interface that Podman exposes.
The preview removes obsolete generated files when it starts.
In a linked Git worktree, the container also mounts the common Git directory read-only.

For LAN access, supply the host's LAN address as `BIND`, for example:

```sh
make serve-bg BIND=192.168.1.10
```

Set `PORT` to change the port. `PREVIEW_URL` overrides the URL Hugo uses for links.

```sh
make diagrams   # Parse the page's Mermaid diagrams.
make render     # Build the site into public/.
```

Stop the preview before a production build, or set `OUT` to a different
directory inside the checkout. Both commands otherwise use `public/`.
Set `PAGE` to check a different Markdown file. `ENGINE=docker` selects Docker,
as used by the CI workflow.

The parser and browser renderer use Mermaid 12.2.0.
Update its pins in `Makefile` and `hugo.yaml` together.

## Native preview

Prerequisites: Node.js (>= 22) and a Go toolchain (Hugo fetches the
Docsy theme as a Hugo module on first build).

```bash
npm ci
npx hugo server
```

Then browse <http://localhost:1313/>. Add `--bind 0.0.0.0` to the
server command when browsing from a different machine.

`npm ci` installs the pinned `hugo-extended` binary and the PostCSS tools
into `node_modules`.
A build without `npm ci` fails with "You need to install PostCSS".

To produce a production build in `public/`, run `npx hugo`.

Do not use `npm run serve` or `npm run build`: those scripts are
inherited from upstream Docsy and reference a `userguide` directory
this repository does not have.

## Content

Documentation lives under `content/en/docs/`.

Two pages are machine-generated and must not be edited directly:

- `content/en/docs/misc/thin_client_api_reference.md`,
  generated by `tools/thin-client-api-gen/`
- `content/en/docs/misc/python_thin_client_api.md`,
  generated by `tools/python-api-gen/`

Edit the binding docstrings, `groups.yaml`, or the `overlay/` fragments.
Then run the generator. Each generator directory has a README with instructions.
